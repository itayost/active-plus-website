# Active Plus website v2: roadmap

The client's v2 brief (two PDFs, 2026-10-04) turns the site from a lead-form brochure into a funnel: **fit check (questionnaire) -> plan choice -> web checkout -> app**. Approved HTML mockups live in `.impeccable/mocks/site/` (open `index.html` via `python3 -m http.server 3200` from the repo root). They are the visual spec for everything below.

The work splits into three plans, each shippable and testable on its own:

| # | Plan | Repo(s) | Depends on | Ships |
|---|------|---------|-----------|-------|
| 1 | [Site pages](2026-10-04-v2-site-pages.md): all six pages, three explainers, nav, content, redirects, legal pages kept | website | none | Can merge first. The payment page shows plans with an in-app purchase fallback. |
| 2 | [Web questionnaire + phone sign-in](2026-10-04-v2-questionnaire.md): the app's sign-up funnel on the web, Supabase phone OTP, answers merged into the user's profile | website + FitnessForSeniorsApp (TypeScript target for the shared funnel contract generator; existing RPCs used as-is) | 1 | Must ship together with or after 1, because the green "בדיקת התאמה" button points at `/questionnaire`. |
| 3 | [Grow checkout + subscriptions](2026-10-04-v2-grow-checkout.md): 4-step purchase, Grow wallet, webhook, `subscriptions` rows the app recognises | website + FitnessForSeniorsApp (migration, `createGrowPayment` / `growWebhook` / `cancelGrowSubscription` edge functions, shared subscription writer) | 1, 2 | Flips the payment page's `NEXT_PUBLIC_WEB_CHECKOUT` flag on. |

## Release order

1. Plans 1 + 2 on a preview deployment, client review, then production together. Until plan 3 ships, "המשך לרכישה" opens the app-store download block, the purchase path that already exists today.
2. Plan 3 on preview against Grow's **sandbox**. One real low-value purchase in production with the client's Grow account, then the flag goes on.

## Fixed decisions (from the conversation, 2026-10-04)

- Pages: Home, About (`/about`), How it works (`/how-it-works`), Questionnaire (`/questionnaire`), Payment (`/payment`), Articles (`/articles`, `/articles/[slug]`). Card explainers at `/personal-plan`, `/motion-detection`, `/progress`, linked only from the home cards.
- **Legal pages stay live, unchanged, at the same URLs:** `/delete-account` (its URL is registered in the App Store and Google Play listings as the account-deletion URL, which both stores require) and `/privacy-policy`. Never redirect, rename or noindex them. They are reachable from the footer.
- Removed pages 301 to their new homes: `/dual-tasking` -> `/how-it-works`, `/research` -> `/about`, `/team` -> `/about`, `/faq` -> `/#faq`, `/contact` -> `/#lead`, `/pricing` -> `/payment`, plus the three old article slugs to the new ones.
- Prices: annual 59 ₪/month = **one charge of 708 ₪**, payable in 1-12 installments, **no auto-renew** (behind a config switch, card token saved so renewal can be turned on later). Monthly 99 ₪, recurring, no commitment. **No free trial.** The savings shown are 480 ₪ (the brief's 600 is arithmetically wrong).
- Processor: Grow (Meshulam). Card data never touches our servers.
- The website and the app share one Supabase project. SMS OTP already runs through the `sendAuthOtpSms` auth hook, so web phone sign-in needs no new SMS setup.
- Lead form on home: name + phone only.
- Partners: keep the existing logo marquee.

## Found while planning

- The questionnaire mockup was built from the app's outdated `docs/funnel-flow.md`. The current funnel is v5 (`docs/superpowers/specs/2026-10-04-funnel-v5.md`); plan 2 Task 0 re-mocks it before building.
- The web derives the funnel's steps and answer keys from the app's shared contract (`shared/funnel-contract/contract.mjs`) through a new TypeScript target in its generator, the same way Swift and Kotlin are derived.
- App-side bugs spotted (not fixed by these plans): `merge_funnel_session` ignores `daily_activity_level`; the iOS paywall shows masculine copy to everyone; Apple Sign-In merges without the existing-user check.
